# DynamicLight fork — контекст проекта

Форк https://github.com/mskutin/DynamicLight (Rust + Tauri 2, UI на JS в `src/ui`).
Цель: стабильная Ambient-подсветка экрана + музыка/эффекты, тихая работа в фоне, автозапуск Windows.
Отвечай по-русски. Пользователь просит экономить токены: не читай большие файлы целиком, используй grep/sed по нужным местам.

## Железо
- Лента ROBOBLOQ (USB HID VID 0x1A86, PID 0xFE07), 94 LED.
- 4 отдельные планки, соединены проводами на углах → **в углах светодиодов нет**.
- Разбивка: слева 16, сверху 31, справа 16, снизу 31.
- Начало: слева снизу (если смотреть на экран), предположительно по часовой стрелке — подтвердить калибровкой.
- Официальная программа SyncLight должна быть закрыта (конфликт за устройство).

## Протокол (сверено с драйвером OpenRGB)
- Короткая команда: `52 42 len id cmd payload.. checksum`, len = payload + 6, checksum = сумма байт & 0xFF. Отправка репортами по 65 байт (первый байт = report ID 0).
- 0x82 — инфо об устройстве. Ответ: `[8]` = диагональ в дюймах, `[11]` = число LED, `[21..23]` = версия прошивки. Иногда ответ приходит только после следующей команды → послать no-op `0x93 00`.
- 0x93 00 — отключает открытие URL «скачайте драйвер» с эмулируемой клавиатуры.
- 0x87 b — яркость, шкала **0–255** (0 трактуется как максимум, слать ≥1).
- 0x86 — заливка диапазонами: `(start, r, g, b, end)`, индексы с 1, включительно.
- 0x80 — кадр: `53 43 lenH lenL id 80 [(start,r,g,b,end)…] checksum`, len = 7 + 5·N. Официальное приложение сжимает кадр до 34 диапазонов.
- Между 64-байтными репортами пауза 1 мс.

## Проблемы оригинала (почему форк)
1. `hidapi error: hid_write/WaitForSingleObject 0x3E5` и «Waiting for strip» — кадр из 94 диапазонов = 8 репортов подряд без пауз, при любой ошибке сразу обрыв.
2. Всего 30 FPS (лента тянет 60).
3. Тусклая яркость: при подключении слалось 0x87 = 100 при шкале 0–255; плюс софт-яркость по умолчанию 38%.
4. Формат кадра был нестандартный (диапазоны с 0, лишний байт) — возможен сдвиг цветов на 1 LED.
5. Раскладка делила периметр равномерно, не учитывая пустые углы.
6. Не гасил ленту при выключении Windows (USB держит питание → горит последний кадр).

## Уже сделано (патч 0001, ветка stable-usb)
- `protocol.rs`: `frame()` в официальном формате + `merge()` (жадное слияние соседних LED с минимальной ошибкой, `MAX_RANGES = 34`).
- `device.rs`: пауза 1 мс между репортами; повтор → переоткрытие → только потом обрыв; `query_info()` читает число LED/диагональ (`Controller::detected`); яркость 255.
- `engine.rs`: `connect_strip()` — при подключении автоматически выставляет `settings.count` из ответа ленты.
- `settings.rs`: поля `side_left/top/right/bottom`, `corner_gap` (0–20 % длины стороны); FPS 10/20/30/45/60, по умолчанию 60.
- `lighting.rs`: `layout()` — точки захвата по сторонам с отступами у углов (fallback на старый `positions()`, если сумма сторон ≠ count).
- `lifecycle_windows.rs`: WM_QUERYENDSESSION/WM_ENDSESSION → `Action::Shutdown` (гасит ленту).
- `sequence.rs`: запись RGB не чаще 30 к/с (лимит 1800 кадров).
- UI (`index.html`, `renderer.js`): поля LEDs left/top/right/bottom, Corner gap %, опции 60/45 FPS.
- Патч 2: `lighting::auto_sides()` при подключении сам заполняет разбивку по сторонам (94 → 16/31/16/31, corner_gap 4 % при первом заполнении); превью ленты в UI (`window.ledLayout` в ui-common.js, studio.js) учитывает стороны и отступы углов.
- Протестировано только: protocol + device (cargo test с заглушкой hidapi, 9/9). Полная сборка ещё не проверялась.

# DynamicLight fork — контекст проекта

Форк https://github.com/mskutin/DynamicLight (Rust + Tauri 2, UI на JS в `src/ui`).
Цель: стабильная Ambient-подсветка экрана + музыка/эффекты, тихая работа в фоне, автозапуск Windows.
Отвечай по-русски. Пользователь просит экономить токены: не читай большие файлы целиком, используй grep/sed по нужным местам.

## Железо
- Лента ROBOBLOQ (USB HID VID 0x1A86, PID 0xFE07), 94 LED.
- 4 отдельные планки, соединены проводами на углах → **в углах светодиодов нет**.
- Разбивка: слева 16, сверху 31, справа 16, снизу 31.
- Начало: слева снизу (если смотреть на экран), предположительно по часовой стрелке — подтвердить калибровкой.
- Официальная программа SyncLight должна быть закрыта (конфликт за устройство).

## Протокол (сверено с драйвером OpenRGB)
- Короткая команда: `52 42 len id cmd payload.. checksum`, len = payload + 6, checksum = сумма байт & 0xFF. Отправка репортами по 65 байт (первый байт = report ID 0).
- 0x82 — инфо об устройстве. Ответ: `[8]` = диагональ в дюймах, `[11]` = число LED, `[21..23]` = версия прошивки. Иногда ответ приходит только после следующей команды → послать no-op `0x93 00`.
- 0x93 00 — отключает открытие URL «скачайте драйвер» с эмулируемой клавиатуры.
- 0x87 b — яркость, шкала **0–255** (0 трактуется как максимум, слать ≥1).
- 0x86 — заливка диапазонами: `(start, r, g, b, end)`, индексы с 1, включительно.
- 0x80 — кадр: `53 43 lenH lenL id 80 [(start,r,g,b,end)…] checksum`, len = 7 + 5·N. Официальное приложение сжимает кадр до 34 диапазонов.
- Между 64-байтными репортами пауза 1 мс.

## Как работает SyncLight 3.15 (Electron, разобран app.asar)
- Захват экрана — нативный модуль `@warren-robobloq/quiklight` в worker-потоке, интервал `syncInterval 10 мс + syncSpeed` (≈100 Гц), samplingRate 10.
- Кадр 0x80 ("SC", len 16-bit BE, id, 0x80, тройки (start,r,g,b,end), checksum = сумма % 256) — **диапазоны с 1, включительно**, число диапазонов = числу зон захвата (~34), LED делятся по зонам поровну (`floor(n/zones)`, остаток в первые зоны).
- Прошивки ≤1.0.2: вместо 0x80 шлёт 0x86 кусками по 55 значений с паузой 20 мс.
- Пишет через node-hid `HIDAsync` без пауз между репортами и без ожидания ответа (`writeWithoutResponse`); ответы читает постоянно (событие `data`). Т.е. **частота и паузы контроллер не вешают**.
- Вывод: вероятная причина зависаний в оригинальном DynamicLight — нестандартный кадр (диапазоны с **0** и лишний байт в конце), прошивка пишет за границу буфера. Наш `frame()` это уже исправил.
- id пакета: 1..254 по кругу. Команды: 0x80 sync, 0x81 writeDeviceInfo, 0x82 readDeviceInfo, 0x83 readUUID, 0x85 effect, 0x86 sectionLED, 0x87 brightness, 0x89 autoOff, 0x8A speed, 0x8B soundSens, 0x91 externalAudio, 0x93 openUrl, 0x95 setLampsAmount, 0x96 whiteBright, 0x97 turnOff, 0x98 computerRhythm.
- Программный перезапуск USB (`pnputil /restart-device`) не помогает: зависший контроллер пропадает до физического переподключения.

## Проблемы оригинала (почему форк)
1. `hidapi error: hid_write/WaitForSingleObject 0x3E5` и «Waiting for strip» — кадр из 94 диапазонов = 8 репортов подряд без пауз, при любой ошибке сразу обрыв.
2. Всего 30 FPS (лента тянет 60).
3. Тусклая яркость: при подключении слалось 0x87 = 100 при шкале 0–255; плюс софт-яркость по умолчанию 38%.
4. Формат кадра был нестандартный (диапазоны с 0, лишний байт) — возможен сдвиг цветов на 1 LED.
5. Раскладка делила периметр равномерно, не учитывая пустые углы.
6. Не гасил ленту при выключении Windows (USB держит питание → горит последний кадр).

## Уже сделано
- `protocol.rs`: `frame()` в официальном формате + `merge()` (жадное слияние соседних LED с минимальной ошибкой, `MAX_RANGES = 34`).
- `device.rs`: пауза 1 мс между репортами; повтор → переоткрытие → только потом обрыв; `query_info()` читает число LED/диагональ (`Controller::detected`); яркость 255.
- `engine.rs`: `connect_strip()` — при подключении автоматически выставляет `settings.count` из ответа ленты.
- `settings.rs`: поля `side_left/top/right/bottom`, `corner_gap` (0–20 % длины стороны); FPS 10/20/30/45/60, по умолчанию 60.
- `lighting.rs`: `layout()` — точки захвата по сторонам с отступами у углов (fallback на старый `positions()`, если сумма сторон ≠ count).
- `lifecycle_windows.rs`: WM_QUERYENDSESSION/WM_ENDSESSION → `Action::Shutdown` (гасит ленту).
- `sequence.rs`: запись RGB не чаще 30 к/с (лимит 1800 кадров).
- UI (`index.html`, `renderer.js`): поля LEDs left/top/right/bottom, Corner gap %, опции 60/45 FPS.
- Патч 2: `lighting::auto_sides()` при подключении сам заполняет разбивку по сторонам (94 → 16/31/16/31, corner_gap 4 % при первом заполнении); превью ленты в UI (`window.ledLayout` в ui-common.js, studio.js) учитывает стороны и отступы углов.
- Capture recovery (`resume_capture`) включён по умолчанию.
- Захват экрана (`capture.rs`): при потере DXGI duplication (UAC, блокировка, смена режима) держим последний кадр, пересоздаём захват 4 раза/с, через 0,3 с приглушаем до 25 %.
- Lock-клавиши: хук + `hold_output` (см. ниже).
- Автонастройка без участия пользователя: при подключении `0x82` даёт число LED и диагональ; `lighting::guess_sides` выбирает 3 или 4 стороны по шагу LED ≈2 см (0.5 LED/см), соотношение сторон — из реального монитора (`capture::display_aspect`). Киты: 24"/27", 3- и 4-сторонние (24": ~56/~83 LED, 27": ~64/~94; порог 69/78). Ручной выбор сторон не перетирается. В UI предупреждение, если сумма сторон ≠ числу LED.
- Windows: Launch at login = задача Планировщика с HighestAvailable (один UAC при переключении), старый Run-ключ удаляется; `ChangeWindowMessageFilter(WM_COPYDATA)` чтобы обычный запуск ярлыка передавал управление админской копии.
- Тёмные сцены (`lighting::lift_dark`, настройка `dark_scenes` 0–100, по умолчанию 35, слайдер в Screen): ниже 40 % яркости цвет масштабируется по кривой с одним множителем на все каналы — оттенок сохраняется, тусклые цвета не гаснут и не уходят в «грязь»; яркие и чёрный не трогаются. (SyncLight «lowLight» на деле — ограничение суммы R+G+B ≤ 255, т.е. тока; не то же самое.)
- FPS 90/120 с пометкой «experimental» (`settings.fps`), следить за Write failures. Без прав администратора (Windows) частота ограничена 30 (`device::effective_fps`/`fps_limit`): выше хук не видит админские окна и Caps Lock даёт вспышки. В UI варианты >30 отключены, под выбором предупреждение и кнопка «Allow administrator rights» (`elevate`: создаёт launch-задачу одним UAC и перезапускает приложение через неё ~4 с).
- Установщик (`windows/installer-hooks.nsh`): после установки один раз спрашивает «Start DynamicLight with Windows?» и вызывает `dynamiclight.exe --setup-tasks [login]` (один UAC). Задачи: `DynamicLight` (вход в систему, `--autostart`) и `DynamicLight Launch` (без триггера, `--from-task`, Parallel). Обычный запуск без прав сам запускает `DynamicLight Launch` и выходит (`autostart_windows::startup`) — ярлыки и «Запустить» в установщике открывают программу от администратора без UAC. Тихие установки/обновления не спрашивают; интерактивная деинсталляция `--remove-tasks`.
- CI форка: только Windows, два параллельных джоба (checks: fmt/тесты/clippy; build: NSIS-установщик в Artifacts), без релизов, апдейтер-пакетов и CLI; везде быстрый release-профиль (без LTO, 16 codegen units) и один ключ кэша, чтобы PR брали кэш из main; `cancel-in-progress`.

## Бэклог (решено с пользователем 30.10.2026)
- Наш Screen-режим визуально заметно лучше SyncLight; режим «fps optimization» у SyncLight рваный — не перенимать.
- Стробоскоп на Caps/Num/Scroll Lock: все режимы, только >30 FPS (на 30 — никогда), белые/случайные вспышки, Write failures = 0. Причина подтверждена USB-дампом (см. ниже): SET_REPORT индикаторов на клавиатурный интерфейс ленты занимает контроллер ~27 мс и сталкивается с кадрами. Фикс: WH_KEYBOARD_LL-хук (только эти 3 клавиши, включая автоповтор) → `device::hold_output(250)`: кадры пропускаются, solid ждёт. При 30 FPS и ниже пауза не включается (кадр раз в 33 мс не пересекается с ~27 мс обработки индикатора). Хук не видит нажатий в окнах администратора (UIPI) → автозапуск через Планировщик с наивысшими правами (`autostart_windows.rs`). Проверено от админа: Claude, Wireshark, Telegram, Chrome — без вспышек. Дамп в окне DynamicLight: кадры НЕ замирали ни разу — хук там не срабатывал (вероятно, его снимала Windows по таймауту: он жил в потоке session-events, который блокируется на событиях движка). Фикс: хук в отдельном потоке + опрос GetAsyncKeyState каждые 4 мс как страховка. ✅ Проверено: в окне DynamicLight больше не мигает.
- Отключить клавиатуру ленты нельзя: `pnputil /disable-device` отказывает («критическое устройство»). Крайний вариант — Zadig/WinUSB на MI_01 (не делали).
- UAC/блокировка: проверено, работает (держим кадр, через 0,3 с приглушаем до 25 %). Win+L гасит ленту — это настройка off_on_lock, так и задумано.

- Дамп USB (Caps Lock, 60 FPS): Windows шлёт SET_REPORT (21 09 0200, интерфейс 1, 1 байт LED: bit0 Num, bit1 Caps, bit2 Scroll) на клавиатурный интерфейс ленты; контроллер отвечает ~27 мс (блокирующе). При удержании lock-клавиши автоповтор шлёт ~30 таких отчётов/с. Хук WH_KEYBOARD_LL не видит нажатия, когда активно окно с правами администратора (UIPI) — отсюда автозапуск от администратора.

## Производительность
- Замер (2560×1440 @165 Гц, RTX 3080 Ti, Screen 60 FPS): ЦП 1,1 %, ОЗУ 20 МБ, GPU 2–9 % (не зависит от того, открыто ли окно) — это была полная копия кадра в CPU каждый кадр.
- Ветка `perf/gpu-downscale`: копия в текстуру с mip-цепочкой → GenerateMips → в CPU читается только уровень с короткой стороной ≥128 px (1440p → 320×180, в 64 раза меньше данных). Если GPU не умеет mips для формата — старый путь. ✅ Проверено: GPU 0,1–2 % (пики до 4 % при перетаскивании окон), картинка та же.

## Релизы и автообновление
- Версия форка 1.0.0+ (выше любой 0.x автора, чтобы апдейтер никогда не предлагал его сборки). Версия должна совпадать в package.json, src-tauri/Cargo.toml, src-tauri/Cargo.lock, control/Cargo.toml, control/Cargo.lock, tauri.conf.json (`node scripts/release.cjs version vX.Y.Z` проверяет).
- Апдейтер: endpoint `https://github.com/BrenOne/DynamicLight/releases/latest/download/latest.json`, свой pubkey в tauri.conf.json, `updates.rs` доверяет только `/BrenOne/DynamicLight/releases/download/v{version}/dynamiclight-desktop-…`.
- Секреты репозитория: `TAURI_SIGNING_PRIVATE_KEY` (содержимое файла ключа) и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Ключ хранится у владельца, в репозитории его нет.
- Выпуск: поднять версию во всех файлах → merge в main → `git tag vX.Y.Z && git push origin vX.Y.Z`. Джоб `release` подписывает установщик и публикует Release с `dynamiclight-desktop-windows-x64-setup.exe`, `.sig` и `latest.json`.

## Процесс
- Новая работа — в ветках `fix/…`/`feature/…`, PR в `BrenOne/DynamicLight` (не в upstream!), сборка на PR, проверка на ленте, merge.
- CI проверяет `cargo fmt --check`, тесты и `clippy -D warnings` — форматировать перед коммитом.
- Коммиты только с заметками — `[skip ci]`.
